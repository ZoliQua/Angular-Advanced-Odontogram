## (b) Drift-guard design + fail-proof evidence

**Design chosen:** keep `app-version.ts`'s `LIB_VERSION` as a hand-written
literal (ng-packagr's secondary-entry-point TS program only includes files
under this package's own `src/` root, so `app-version.ts` cannot `import`
`package.json` directly — confirmed unchanged from the Task-5 finding), and
make the existing `app-version.spec.ts` drift guard (added in Task 5,
previously running only under `ng test`) also run under `test:corpus`, by
adding it as an explicit extra `include` entry in `vitest.config.ts`
(outside the `core/__tests__` tree, since it guards a non-core, Angular
shim-level concern, not part of the frozen upstream corpus):

```ts
include: [
  "projects/angular-advanced-odontogram/src/lib/core/**/__tests__/**/*.{test,spec}.{ts,tsx}",
  // Task 7 drift guard: ... (see vitest.config.ts's own comment)
  "projects/angular-advanced-odontogram/src/lib/app-version.spec.ts",
],
```

A build-time derivation (reading `package.json` from `app-version.ts`
itself) was rejected for the same reason Task 5 rejected it: ng-packagr's
secondary-entry-point program does not resolve JSON imports from outside
`src/`, and there is no other supported build-time customization point for
this package's lib build (`ng-packagr` has no webpack/vite-style `define`
step of its own). The chosen fix is the minimal one: no source-level
behavior changes, just widening which files the corpus runner executes.
