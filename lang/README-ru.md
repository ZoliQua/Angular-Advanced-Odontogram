## 🇷🇺 Русский

### 📋 Обзор

Данный проект представляет собой интерактивный браузерный редактор одонтограммы для **Angular + TypeScript**, обеспечивающий быстрое заполнение зубной карты с удобным интерфейсом. Компонент отображает многослойные SVG-шаблоны зубов для представления реставраций, кариеса, эндодонтического статуса, подвижности и других клинических данных, а также поддерживает множественный выбор, фильтры выделения и предустановленные статусные шаблоны.

**Это официальный Angular-порт [React Advanced Odontogram](https://github.com/ZoliQua/React-Advanced-Odontogram)** (npm: [`react-advanced-odontogram`](https://www.npmjs.com/package/react-advanced-odontogram)). Паритет функциональности с react-advanced-odontogram **v2.6.0** (коммит движка `215c43a`), версия payload **2.22** — экспорт JSON и FHIR R4 совместимы между двумя библиотеками в обе стороны. Клинический движок (`projects/angular-advanced-odontogram/src/lib/core/`) переиспользуется дословно — логика статуса зубов, пародонтальное картирование, кодирование диагнозов, экспорт/импорт FHIR, строки i18n, направляемый тур и SVG-шаблоны побайтово идентичны оригиналу на React и копируются заново из зафиксированного коммита апстрима при каждой синхронизации; только оболочка компонентов (`projects/angular-advanced-odontogram/src/lib/components/`) написана нативно для Angular. Существует небольшой, явно задокументированный набор отклонений (только строки брендинга/идентификации — см. спецификацию дизайна порта в этом репозитории). Версионирование синхронизировано (lockstep) с React-модулем.

### 📦 Использование в качестве npm-пакета

Одонтограмма поставляется в виде самодостаточной библиотеки Angular-компонентов на npm:
[`angular-advanced-odontogram`](https://www.npmjs.com/package/angular-advanced-odontogram).

#### Требования
- **Angular 21.2+** (объявлен как peer-зависимость — предоставляется вашим приложением).
- **Сборщик**, понимающий поле `exports` и ESM — Angular CLI (`@angular/build`) подходит «из коробки». Пакет **только ESM**.
- Node **≥ 20** для инструментария.

#### Установка

```bash
npm install angular-advanced-odontogram
```

#### Базовое использование

Зарегистрируйте таблицу стилей **один раз**, там, где настраиваются глобальные стили вашего приложения (например, `angular.json`):

```json
"styles": [
  "node_modules/angular-advanced-odontogram/styles.css",
  "src/styles.css"
]
```

Затем отрисуйте `OdontogramShellComponent`:

```ts
import { Component } from "@angular/core";
import { OdontogramShellComponent } from "angular-advanced-odontogram";

@Component({
  selector: "app-chart",
  imports: [OdontogramShellComponent],
  template: `
    <aao-odontogram-shell
      language="en"           
      numberingSystem="FDI"   
      [darkMode]="false"
    />
  `,
})
export class ChartComponent {}
```

`language` принимает значения `hu | en | de | es | it | sk | pl | ru | pt-br | zh | ar | fr`; `numberingSystem` принимает `FDI | UNIVERSAL | PALMER`.

#### Входные параметры компонента

`OdontogramShellComponent` — управляемый компонент: каждый входной параметр — это Angular-сигнал `input()`, все они необязательны и при отсутствии используют собственное значение движка по умолчанию. Наиболее часто используемые:

| Входной параметр | Тип | По умолчанию | Описание |
|------|------|---------|-------------|
| `language` | `Language` | `"hu"` | Язык интерфейса (`hu`/`en`/`de`/`es`/`it`/`sk`/`pl`/`ru`/`pt-br`/`zh`/`ar`/`fr`). |
| `numberingSystem` | `"FDI" \| "UNIVERSAL" \| "PALMER"` | `"FDI"` | Система нумерации зубов. |
| `darkMode` | `boolean` | `false` | Переключатель тёмной темы. |
| `readOnly` | `boolean` | `false` | Отключить всё редактирование (только просмотр). |
| `themeConfig` | `OdontogramThemeConfig` | — | Переопределить CSS-переменные темы (`--odon-*`). |
| `plugins` | `OdontogramPlugin[]` | — | Зарегистрировать пользовательские плагины состояния / дополнительные слои. |
| `enableNotes` | `boolean` | `false` | Включить заметки по каждому зубу. |
| `enableIcdas` | `boolean` | `false` | Включить оценку кариеса по ICDAS II. |
| `fillingComplexity` | `"complex" \| "simple"` | `"complex"` | Сложность карточки пломб: `"simple"` (один материал на зуб) или `"complex"` (материалы по поверхностям). |
| `fillingDefectEnabled` | `boolean` | `true` | Включает фиксацию дефектов пломбы на карточке «Пломбы». |
| `fillingMaterialAvailability` | `Record<string, boolean>` | все доступны | Доступные пломбировочные материалы в виде логической карты по `amalgam`/`composite`/`gic`/`temporary` (неизвестные ключи игнорируются). |
| `fissureSealingEnabled` | `boolean` | `true` | Включает герметизацию фиссур на карточке «Пломбы». |
| `languageChange` / `numberingChange` / `darkModeChange` (выходы) | `output<T>` | — | Срабатывают, когда пользователь меняет соответствующую настройку из интерфейса. |
| `fillingComplexityChange` / `fillingDefectEnabledChange` / `fillingMaterialAvailabilityChange` / `fissureSealingEnabledChange` (выходы) | `output<T>` | — | Срабатывают, когда пользователь меняет соответствующую настройку в Настройки → Пломбы. |

Также принимаются более тонкие входные параметры уровня детализации (`pulpDetailLevel`, `secondaryCariesMode`, `rootCariesMode`, `radiographicDepthMode`, `cariesDepthEnabled`, `wearDetailLevel`, `discolorationDetailLevel`, `surfaceNotation`, `showStatusCard`, `showOrthoCard`) — полный типизированный список см. в `odontogram-shell.component.ts`.

Четыре входных параметра пломб выше действуют **только на восстановление**: пропущенный параметр никогда не записывается в движок (императивный вызов `setFillingComplexity()` до монтирования сохраняется), а переданный параметр записывает и движок, и состояние модального окна настроек одновременно, поэтому окно никогда не показывает устаревшее значение. `fillingMaterialAvailability` применяется через diff по каноническому сериализованному ключу, поэтому повторный рендер с новым литералом объекта идентичного содержимого никогда не перезаписывает движок. Соответствующие выходы `*Change` срабатывают из Настройки → Пломбы — это путь обратной записи для хостов, сохраняющих пользовательские настройки.

#### Публичный API (именованные экспорты)

`OdontogramShellComponent` является именованным экспортом. Императивный API состояния, самостоятельный компонент `PerioChartComponent`, направляемый тур и все публичные типы являются именованными экспортами из той же точки входа:

```ts
import {
  OdontogramShellComponent,
  PerioChartComponent,          // standalone periodontal chart
  // read state
  getOdontogramSummary,
  getToothStateSummary,
  onStateChange,                // subscribe to state changes
  // export / import
  exportFhir,                   // HL7 FHIR R4 bundle
  exportSvg, exportImage,       // vector / raster chart export
  setImportFormat,
  // control
  setReadOnly, getReadOnly,
  clearSelection, getSelectedTeeth,
  registerPlugins, setPluginState, getPluginState,
  startIntroTour,               // launch the onboarding tour
  // …and many more setX/getX settings functions
} from "angular-advanced-odontogram";
```

Полная поверхность API (более 100 функций и типов — `OdontogramSummary`, `OdontogramThemeConfig`, `OdontogramPlugin`, `FhirExportOptions`, `PdfSettings`, `PerioViewMode` и многие другие) полностью типизирована во встроенных объявлениях `.d.ts`; см. таблицу ниже в разделе [Публичный API](#-публичный-api) для отобранного справочника.

#### Компонуемые поверхности (продвинутый уровень)

`OdontogramShellComponent` — это поддерживаемый компонент «всё в одном», не требующий дополнительной настройки. Если вам нужно разместить области одонтограммы в разных частях собственной вёрстки, четыре поверхности интерфейса оболочки также экспортируются и могут быть скомпонованы под одним `OdontogramUiService`, при этом все они используют один сеанс, привязанный к экземпляру сервиса:

```ts
import { AfterViewInit, Component, OnDestroy, inject } from "@angular/core";
import {
  OdontogramUiService,
  OdontogramTopbarComponent,
  OdontogramChartSurfaceComponent,
  ToothInfoSurfaceComponent,
  ToothControlsSurfaceComponent,
} from "angular-advanced-odontogram";

@Component({
  selector: "app-workspace",
  imports: [
    OdontogramTopbarComponent,
    OdontogramChartSurfaceComponent,
    ToothInfoSurfaceComponent,
    ToothControlsSurfaceComponent,
  ],
  providers: [OdontogramUiService],   // one instance = one session, scoped to this host
  template: `
    <my-header-area><aao-odontogram-topbar /></my-header-area>
    <my-main-area>
      <aao-odontogram-chart-surface />
      <aao-tooth-info-surface />
    </my-main-area>
    <my-side-panel><aao-tooth-controls-surface /></my-side-panel>
  `,
})
export class WorkspaceComponent implements AfterViewInit, OnDestroy {
  protected readonly ui = inject(OdontogramUiService);

  constructor() {
    // Every `OdontogramUiConfig` field is optional — a zero-config
    // `configure()` call gives a standalone session with the same defaults
    // `OdontogramShellComponent` itself falls back to (language "en"/"hu"
    // depending on host document, "FDI" numbering, light mode, ...). Pass
    // only the Signals/callbacks you want to override, e.g.
    // `{ darkMode: this.darkMode, onDarkModeChange: (v) => ... }`.
    this.ui.configure();
  }

  ngAfterViewInit(): void { this.ui.init(); }
  ngOnDestroy(): void { this.ui.destroy(); }
}
```

`OdontogramUiService` принимает ту же форму конфигурации, что и входные параметры `OdontogramShellComponent` (его метод `configure()` принимает объект `OdontogramUiConfig` из `Signal`ов/колбэков, каждое поле необязательно и имеет то же значение по умолчанию, что и выше по цепочке). Текущее ограничение: один экземпляр `OdontogramUiService` на страницу (движок — синглтон на уровне модуля). Поверхности можно монтировать и размонтировать по требованию. Сам `OdontogramShellComponent` не изменился — это именно такая композиция в компоновке по умолчанию, по-прежнему явно связывающая каждое поле со своими собственными входными параметрами.

Для ещё более тонкой композиции также экспортируются отдельные карточки управления:

| Компонент | Селектор | Охват |
|---|---|---|
| `StatusesCardComponent` | `aao-statuses-card` | Элементы управления статусами/шаблонами по всей полости рта (сброс, молочный/сменный прикус, беззубый, дополнительные статусы) |
| `ToothDetailsCardComponent` | `aao-tooth-details-card` | Базовая строка (выбор зуба/субстрат), флажки сломанной коронки, переключатели «требуется коронка»/«требуется замена коронки» |
| `CariesCardComponent` | `aao-caries-card` | Режим глубины кариеса, подкоронковый кариес, тяжесть кариеса корня, селектор кариеса по поверхностям |
| `FillingsCardComponent` | `aao-fillings-card` | Материал пломбы, селектор пломбы по поверхностям + дефекты, подсказки о вторичном кариесе/дефекте |
| `RootPeriodontiumCardComponent` | `aao-root-periodontium-card` | Статус пульпы/эндо, апикальный диагноз, резорбция, подвижность, статус периимплантных тканей |
| `OrthodonticsCardComponent` | `aao-orthodontics-card` | Аппарат, дрейф, вертикальное перемещение, ротация |
| `SurfaceCrossComponent` | `aao-surface-cross` | Общий виджет крестообразного выбора поверхностей B/M/O/D/L, используемый внутри карточек кариеса/пломб |
| `DiagnosesCardComponent` | `aao-diagnoses-card` | Кодирование диагнозов по каждому зубу ICD-10/BNO-10/ICD-10-CM/SNOMED — просмотр производных диагнозов зуба и их курирование (подавить производный диагноз, добавить диагноз, не представленный картой) |

Каждая карточка — это самодостаточный декларативный компонент, который читает и записывает общий сеанс через `inject(OdontogramUiService)` и экспортируемый помощник `engineState()` (сигнальное чтение любого геттера движка, поддерживаемое актуальным через собственную шину уведомлений об изменениях ядра). Монтируйте только те карточки, которые нужны конкретной компоновке, в любом порядке, под одним `OdontogramUiService`. `CreditsModalComponent` (`aao-credits-modal`, всплывающее окно верхней панели «О программе и благодарности») и `CaseDiagnosesModalComponent` (`aao-case-diagnoses-modal`, всплывающее окно диагнозов по всей полости рта/регионам) также экспортируются — для хостов, которые хотят управлять любым из них из собственного состояния открытия/закрытия.

```ts
import { engineState, OdontogramUiService, getOdontogramSummary } from "angular-advanced-odontogram";

// Anywhere inside an injection context under an `OdontogramUiService`:
readonly summary = engineState(getOdontogramSummary); // Signal<OdontogramSummary>, kept fresh automatically
```

#### Точки внедрения зависимостей для тестирования хоста

Два `InjectionToken` позволяют приложению-хосту переопределить вызовы движка с побочными эффектами в собственных тестах (оба по умолчанию используют реальный вызов движка в production; оба объявлены как `providedIn: "root"`):

| Токен | Переопределяет | Форма |
|---|---|---|
| `ODONTOGRAM_ENGINE_LIFECYCLE` | `initOdontogram()` / `destroyOdontogram()`, вызывается из `ngAfterViewInit()`/`ngOnDestroy()` компонента `OdontogramShellComponent` | `{ init: () => Promise<void>; destroy: () => void }` |
| `EXPORT_PDF_FN` | `exportPdf(opts)`, вызывается из `ExportOptionsModalComponent` при нажатии «Экспорт» | `(opts: PdfExportOptions) => Promise<void>` |

Оба существуют потому, что реальные функции обращаются к внутренним механизмам DOM/canvas/`jsPDF`, которые headless-среда тестирования не может полностью предоставить — переопределяйте их через массив провайдеров `TestBed` Angular в собственных тестах компонентов приложения-хоста.

#### Важные замечания и текущие ограничения
- **Только ESM** — пакет публикует единый ES-модуль (собранный с помощью `ng-packagr`) плюс точку входа для деклараций типов. Он ориентирован на разрешение модулей сборщиком; сборки CommonJS не существует.
- **Таблица стилей отдельная** — вы **обязаны** зарегистрировать `angular-advanced-odontogram/styles.css` один раз; она не подключается автоматически. Стилизация — это глобальный CSS, ограниченный областью `.odontogram-root` и управляемый CSS-переменными `--odon-*`.
- **SSR / только клиент** — компонент обращается к DOM при монтировании, поэтому он должен выполняться в браузере; отрисовывайте его только на стороне браузера.
- **Ресурсы самодостаточны** — SVG зубов и иконок встраиваются в бандл на этапе сборки (сгенерированные TypeScript-модули, `npm run gen:assets`); **не требуется настраивать загрузку ресурсов во время выполнения**, и нечего дополнительно копировать в публичную папку вашего приложения.
- **Загрузка по требованию** — в исходный бандл входят только английский язык и графика анатомии зубов `classic`; таблицы 11 остальных языков интерфейса и графика профиля анатомии `measured` загружаются отдельными ленивыми частями (chunks) при первом переключении хоста на них (`setI18nLanguage`/меню языка и `setToothAnatomy("measured")`/Настройки → Одонтограмма → анатомия зубов соответственно). Это разделение при данной синхронизации сократило основной чанк демо-приложения с 3,12 МБ до 1,23 МБ, а исходный общий объём — с 3,21 МБ до 1,32 МБ — на стороне хоста настраивать ничего не нужно.
- **Один экземпляр на страницу** в этом релизе — состояние движка является синглтоном на уровне модуля (как и в оригинале на React), поэтому отрисовка двух экземпляров `<aao-odontogram-shell>` на одной странице приведёт к тому, что они будут использовать общее состояние одной карты.

- 🔀 Разделение карты «Статус ↔ План»: переключатель `Статус | План` переключает между текущей картой **статуса** и картой **плана** (предполагаемое лечение), каждая со своими состояниями зубов; экспорт/импорт всегда относятся к карте статуса, тогда как карта плана читается/записывается отдельно через собственный API (см. [Публичный API](#-публичный-api)) и — если она отличается от статуса — включается в экспорт JSON как дополнительный раздел `plan`
- 📝 Блок «Что изменится»: когда план отличается от текущего статуса, перечисляет каждое различие по зубу и по оси лечения; также доступен программно через `getPlanChanges()`
- 🅿️ Предлагаемое оформление: в режиме «План» находки, которые план **добавляет** по сравнению с текущим статусом, отображаются отдельным пунктирным, тонированным контуром «предлагается»
- 🚦 Ограничение режима «План»: карта «План» показывает только то, что стоматолог может *сделать* — находки, относящиеся только к статусу (кариес, стирание зубов, изменение цвета, весь пародонтальный блок), скрыты; реставрация, протезирование, ортодонтия, необходимость/замена коронки и план удаления остаются доступными для планирования

`none`, `healing-abutment`, `locator`, `locator-denture`, `bar`, `bar-denture` (аттачменты имплантата, с покрывным протезом или без него), `removable-partial`, `removable-full` (съёмные протезы с опорой на зубы на отсутствующем зубе/дефекте). **Краевая негерметичность коронки** (`crownLeakage`; логическое значение): отображается только когда `restorationType` равен `crown` или `bridge`.

**Эндодонтические варианты (молочные зубы):**
`none`, `endo-medical-filling`

**Диагноз пульпы** (терминология AAE; `pulpDx`):
`normal`, `reversible-pulpitis`, `irreversible-pulpitis`, `necrosis` — взаимоисключающий с `endo`

**Апикальный диагноз** (`apicalDx`; определяет периапикальный глиф):

`none`, `internal`, `external-cervical`

**Тяжесть кариеса** (`cariesSeverity`; единое поле по поверхности, `0`–`6`): на поверхности без пломбы читается как шкала глубины кариеса ICDAS (`superficial` / `dentin` / `deep`, либо необработанные коды ICDAS II `0–6` при включённом `enableIcdas`); на поверхности с пломбой читается как именованная оценка CARS (`0` здоров … `6` обширная полость)

**Настройки детализации кариеса** (глобальные): `secondaryCariesMode` (`simple`/`standard`/`full`, по умолчанию `standard`), `rootCariesMode` (`simple`/`severity`, по умолчанию `simple`), `radiographicDepthMode` (`off`/`threeLevel`/`detailed`, по умолчанию `off`), `cariesDepthEnabled` (логическое значение, по умолчанию `true`)

`crownNeeded`, `crownReplace`, `missingClosed`, `extractionPlan`, `extractionWound`, `bridgePillar`, `fissureSealing`, `contactMesial`, `contactDistal`, `endoResection`, `calculus`, `parapulpalPin`

`none`, `tetracycline`, `fluorosis`, `nonvital`, `extrinsic`, `other`

`none`, `marginal`, `fracture`, `wear`

### ⚙️ Настройки

Открывается по значку шестерёнки на верхней панели (`SettingsModalComponent`); модальное окно `dialog` ARIA с блокировкой фокуса и раскладкой из 7 вкладок (Esc/клик по фону для закрытия, стрелки для переключения вкладок). Диалог — это чистое представление над предоставленным хостом `SettingsState`, он сам не владеет состоянием настроек. Все настройки являются состоянием интерфейса только на уровне сессии, если не указано иное — ни одна из них не изменяет данные по зубам или экспортируемый payload.

- **Общие:** система нумерации (FDI/Universal/Palmer), язык, тёмная/светлая тема, доступность экспорта по формату (PNG/JPG/SVG/PDF — скрывает соответствующий пункт меню экспорта при отключении и делает недоступной вкладку «Экспорт», если PDF отключён), доступность импорта по источнику (Статус JSON/FHIR), пакет кодирования диагнозов (нет / BNO-10 / ICD-10-CM) и опциональный переключатель оверлея SNOMED CT
- **Одонтограмма:** экранная раскладка — интервал между зубами, размер номера зуба, цвет выделения и стиль рамки; видимость панели информации о зубах; доступность режима «План»; профиль анатомии зубов (`classic` по умолчанию / `measured` — девять шаблонов зубов, измеренных по литературным источникам, в раскладке из двух дуг с индивидуальной шириной зуба, переключается во время работы; его графика загружается отдельной ленивой частью только при переключении на него, поэтому вариант `classic` по умолчанию ничего не стоит); видимость карточки статусов и карточки ортодонтии
- **Периодонтальная карта:** переключатель доступности, управляющий остальной частью вкладки и точками входа пародонтальной карты в оболочке; режим отображения пародонтальной карты (`toggle`/`popup`); 16 переключателей показать/скрыть по каждому индексу, сгруппированных в 5 групп (Карманы: PD/GM/CAL/BOP · Гигиена: зубной налёт/PI/GI · Мукогингивальные параметры: видимость CEJ/вогнутость корня/KG/GT · Поддержка: фуркация/подвижность/класс Миллера · Периимплантные: mPI/mBI); режим отображения названия индекса переведённое/каноническое (каноническое = фиксированное научное название на английском/латыни на любом языке интерфейса; всплывающие подсказки всегда остаются локализованными)
- **Детали зуба:** уровень детализации пульпы (simple/AAE/практический латинский, по умолчанию AAE), уровень детализации стирания и уровень детализации изменения цвета (simple/complex, каждый по умолчанию complex), нотация поверхностей (simple/full, по умолчанию full), переключатель заметок к зубам
- **Кариес:** переключатель оценки ICDAS II, переключатель глубины кариеса, детализация кариеса корня (simple/severity), детализация вторичного кариеса/CARS (simple/standard/full), детализация рентгенологической глубины (off/threeLevel/detailed)
- **Пломбы:** сложность пломбы (complex/simple), переключатель находок дефектов пломбы, доступность по материалу (amalgam/composite/gic/temporary), переключатель герметизации фиссур
- **Экспорт:** полная конфигурация PDF-отчёта (`PdfSettings` — см. [Экспорт](#-экспорт) ниже) — недоступна (возвращается к содержимому вкладки «Общие»), когда экспорт PDF отключён на вкладке «Общие»

### 🔢 Системы нумерации

**FDI (ISO 3950):** зубы взрослых 11-18, 21-28, 31-38, 41-48. Молочные зубы 51-55, 61-65, 71-75, 81-85. Значение: `"FDI"`.

**Universal (США):** зубы взрослых пронумерованы 1-32. Молочные зубы обозначены буквами A-T. Значение: `"UNIVERSAL"`.

**Palmer (Zsigmondy-Palmer):** формат квадрант + позиция (например, UR-1, LL-5). Молочные зубы обозначены буквами A-E в каждом квадранте. Значение: `"PALMER"`.

`NumberingSystem` (`core/utils/numbering.ts`) — это точное объединение типов `"FDI" | "UNIVERSAL" | "PALMER"`; экспортируемая функция `toLabel(fdiTooth, system)` преобразует номер зуба по FDI в метку запрошенной системы (например, `toLabel(14, "PALMER")` → `"UR-4"`).

### 🔗 Интеграция
Компонент можно встроить в любое Angular-приложение:
```ts
import { Component } from "@angular/core";
import { OdontogramShellComponent } from "angular-advanced-odontogram";
import type { Language } from "angular-advanced-odontogram";
import type { NumberingSystem } from "angular-advanced-odontogram";

@Component({
  selector: "app-host",
  imports: [OdontogramShellComponent],
  template: `
    <aao-odontogram-shell
      [language]="language"
      (languageChange)="onLanguageChange($event)"
      [numberingSystem]="numbering"
      (numberingChange)="onNumberingChange($event)"
      [darkMode]="darkMode"
      (darkModeChange)="onDarkModeChange($event)"
    />
  `,
})
export class HostComponent {
  language: Language = "en";
  numbering: NumberingSystem = "FDI";
  darkMode = false;

  onLanguageChange(lang: Language) { this.language = lang; console.log(lang); }
  onNumberingChange(system: NumberingSystem) { this.numbering = system; console.log(system); }
  onDarkModeChange(dark: boolean) { this.darkMode = dark; console.log(dark); }
}
```

**Интеграция тёмного режима:**
- **Автономный режим:** Опустите `darkMode` — компонент самостоятельно управляет состоянием темы через кнопку переключения на верхней панели и добавляет/удаляет класс `.dark` на корневом элементе хоста.
- **Управляемый режим:** Свяжите `[darkMode]` и `(darkModeChange)` — родительское приложение управляет темой. Кнопка переключения по-прежнему отображается, но вызывает `darkModeChange` вместо управления внутренним состоянием. Родительское приложение отвечает за добавление/удаление класса `.dark` на `<html>`.

**Пользовательская тема:**
```ts
@Component({
  template: `<aao-odontogram-shell [themeConfig]="theme" />`,
})
export class ThemedHostComponent {
  readonly theme = {
    colors: {
      accent: "#e74c3c",
      background: "#fafafa",
      text: "#222222",
    },
  };
}
```

**Интеграция плагинов:**
```ts
import type { OdontogramPlugin } from "angular-advanced-odontogram";
import { setPluginState } from "angular-advanced-odontogram";

const myPlugin: OdontogramPlugin = {
  id: "implant-brand",
  label: { en: "Implant Brand", hu: "Implantátum márka" },
  layer: "overlay",
  renderSvg: (toothNo, _quadrant, state) => {
    if (!state) return null;
    return `<text x="16" y="60" font-size="6" fill="#3b7bff">${state}</text>`;
  },
};

// <aao-odontogram-shell [plugins]="[myPlugin]" />

// Set plugin state for a tooth:
setPluginState(11, "implant-brand", "Straumann");
```

Вывод `renderSvg()` плагина санитизируется библиотекой DOMPurify (SVG-профиль) перед вставкой в живую карту — см. [Примечания по безопасности](#-примечания-по-безопасности).

### 🧪 Тестирование

Набор тестов разделён на **два раннера**, и оба должны проходить успешно (`npm test` запускает оба по очереди):

### 💾 Сохранение состояния (localStorage)

Опциональное сохранение состояния случая одонтограммы в `localStorage` (`core/persistence.ts`, реэкспортируется из точки входа пакета). По умолчанию отключено — существующие интеграции не затрагиваются, если приложение-хост явно не включит эту функцию, и вызывать её следует **после** монтирования одонтограммы (например, из `ngAfterViewInit()` компонента, после того как `OdontogramShellComponent`/`OdontogramUiService` вызвал `init()` — восстановление перерисовывает живой DOM через `importStatus()`):

```ts
import {
  enablePersistence, disablePersistence,
  clearPersistedState, isPersistenceEnabled,
} from "angular-advanced-odontogram";

enablePersistence({
  key: "my-app-odontogram",   // default: "react-advanced-odontogram" (the shared core's own default key)
  includePlan: true,          // also persist the plan chart; default: false
  onError: (err) => console.error("odontogram persistence:", err),
});
```

| Функция | Описание |
|---|---|
| `enablePersistence(options?)` | Восстанавливает ранее сохранённый случай (если он есть) через `importStatus()`, затем сохраняет статусную карту в `localStorage` при каждом устоявшемся изменении состояния (правки группируются и откладываются на ~400 мс, так что серия изменений — например, применение статусного шаблона — приводит к одной записи; приём известен как «debounce»/«дебаунсинг»). Идемпотентна — повторный вызов заменяет предыдущую подписку/опции. **Должна вызываться после монтирования одонтограммы.** |
| `disablePersistence()` | Останавливает сохранение (предварительно сбрасывая любое отложенное сохранение); сохранённая запись остаётся на месте. |
| `clearPersistedState()` | Удаляет сохранённую запись для активного (или стандартного) ключа. |
| `isPersistenceEnabled()` | `true`, пока подписка на изменение состояния активна. |

**`PersistenceOptions`:**

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `key` | `string` | `"react-advanced-odontogram"` | Ключ `localStorage` — это собственное буквальное значение по умолчанию общего модуля ядра (не изменено Angular-портом); передайте собственный `key`, чтобы избежать коллизии с интеграцией на стороне React на том же источнике, или для разграничения нескольких хостов по пространствам имён. |
| `includePlan` | `boolean` | `false` | Также сохранять карту плана (поле `plan` в payload). |
| `onError` | `(err: Error) => void` | — | Вызывается при любой ошибке хранения/парсинга вместо `console.warn`. |

Примечания: ничего не читается из `localStorage` и не записывается в него, пока не вызвана `enablePersistence()`; ограничение размера 4 МБ пропускает слишком большое сохранение (сообщается через `onError`/`console.warn`), вместо того чтобы выбросить исключение; любой сбой хранения/JSON — превышение квоты, заблокированный iframe, повреждённые или нераспознанные сохранённые данные и т. д. — перехватывается и сообщается. Этот модуль никогда не выбрасывает исключения.

Примечание: включение сохранения восстанавливает сохранённый случай через `importStatus()`, что заменяет текущий случай — включая незавершённую карту плана, если в сохранённых данных её нет. Включайте сохранение при запуске (сразу после монтирования), а не в середине сеанса.

Примечание: сохранённые данные могут содержать идентифицирующую пациента информацию (имя пациента, дата осмотра) в открытом виде в `localStorage`. Если вы фиксируете такие данные, обеспечьте защиту на уровне устройства или удаляйте их с помощью `clearPersistedState()`, когда это уместно.

### 💾 Формат экспорта/импорта статуса
Экспорт создаёт файл JSON (версия `2.22`; импорт также принимает устаревшие версии `1.4` и `2.0`–`2.21` и автоматически мигрирует их), содержащий:

**Глобальные поля:**
- `wisdomVisible` — видимость зубов мудрости
- `showBase` — видимость слоя кости
- `occlusalVisible` — активность окклюзионного вида
- `showHealthyPulp` — видимость здоровой пульпы
- `edentulous` — активность режима беззубого

**Поля для каждого зуба (32 зуба):**
- `toothSelection` — базовый тип зуба
- `toothSubstrate` — субстрат зуба (natural/radix/broken/crownprep), независим от вида реставрации
- `restorationType` — тип реставрации (none/crown/inlay/onlay/veneer/bridge)
- `restorationMaterial` — материал реставрации (emax/gold/gradia/zircon/metal/metal-ceramic/telescope/temporary), сопряжён с `restorationType`
- `prosthesis` — ось съёмного/аттачментного протезирования (none/healing-abutment/locator/locator-denture/bar/bar-denture/removable-partial/removable-full), взаимоисключающая с фиксированным `restorationType` коронка/мост
- `crownLeakage` — флаг краевой негерметичности коронки, имеет значение только когда `restorationType` равен crown или bridge
- `endo` — эндодонтический статус; взаимоисключающий с `pulpDx`
- `mods` — массив модификаций (inflammation, parodontal); `inflammation` применяется только к отсутствующим зубам/лункам после удаления
- `caries` — активные поверхности кариеса
- `cariesActiveDepth` — значение глубины ICDAS, устанавливаемое селектором глубины кариеса при применении к новой поверхности
- `rootCaries` — степень тяжести кариеса корня (none/active/arrested/active-cavitated)
- `cariesSeverity` — единая тяжесть по поверхностям (0-6): глубина ICDAS на первичной (без пломбы) поверхности, оценка CARS на рецидивирующей (с пломбой) поверхности
- `radiographicDepth` — рентгенологическая глубина кариеса по поверхностям (none/E1/E2/D1/D2/D3), независимая от визуальной шкалы ICDAS/CARS
- `fillingMaterial` — материал пломбы
- `fillingSurfaces` — запломбированные поверхности
- `fillingSurfaceMaterials` — материал пломбы по поверхностям (смешанные пломбы, например щёчная амальгама + дистальный композит)
- `fillingDefect` — дефект пломбы по поверхности (none/marginal/fracture/wear), ограничен запломбированными поверхностями, независим от вторичного кариеса
- `pulpDx` — диагноз пульпы по AAE (normal/reversible-pulpitis/irreversible-pulpitis/necrosis)
- `pulpLatin` — практический латинский подтип пульпы (селектор пульпы показывает его только когда `pulpDetailLevel` равен `latin`)
- `apicalDx` — апикальный диагноз, определяющий периапикальный глиф
- `periapicalType` — подтип периапикального очага (none/granuloma/cyst); устаревшее значение `abscess` по-прежнему принимается при импорте
- `resorptionType` — тип резорбции корня (none/internal/external-cervical)
- `periImplant` — статус периимплантных тканей только для имплантатов (none/mucositis/peri-implantitis-mild/-moderate/-severe), стадирование по классификации Всемирного семинара 2018 года
- `dxOverrides` — переопределения кодирования диагнозов по зубу (версия 2.21): объект, где ключ — ключ диагноза ICD-10, а значение — `add` | `suppress`, принудительно включающий закодированный диагноз при отсутствии соответствующей находки карты, либо выключающий его при её наличии; формирует эффективный закодированный набор, экспортируемый как FHIR `Condition`
- `endoResection` — флаг апикоэктомии
- `fissureSealing` — флаг герметизации фиссур
- `calculus` — флаг зубного камня
- `contactMesial` / `contactDistal` — потеря мезиального/дистального контактного пункта
- `wearEdge` — тип стирания режущего края/окклюзионной поверхности (none/attrition/erosion)
- `wearCervical` — тип пришеечного стирания (none/abrasion/abfraction/erosion)
- `discoloration` — причина изменения цвета по зубу (none/tetracycline/fluorosis/nonvital/extrinsic/other)
- `orthoAppliance` — ортодонтический аппарат (none/bracket/band)
- `orthoDrift` — ортодонтический дрейф (none/mesial/distal)
- `orthoVertical` — ортодонтическое вертикальное перемещение (none/extrusion/intrusion)
- `orthoRotation` — флаг ортодонтической ротации
- `brokenMesial`, `brokenIncisal`, `brokenDistal` — локализация переломов
- `extractionWound` — лунка после удаления
- `extractionPlan` — планируемое удаление
- `parapulpalPin` — флаг парапульпарного штифта
- `bridgePillar` — зуб-опора мостовидного протеза
- `mobility` — степень подвижности (none/m1/m2/m3)
- `crownNeeded` — индикатор необходимости коронки
- `crownReplace` — индикатор необходимости замены коронки
- `missingClosed` — закрытый дефект после удаления
- `customStates` — пользовательские состояния плагинов (объект с ключами по ID плагина)
- `note` — текстовая заметка к зубу (строка, необязательная — присутствует только при наличии содержимого)

**Поле верхнего уровня `plan` (версия 2.11+):**
- `plan` — необязательный объект той же формы, что и `teeth` (поля по зубам выше), содержащий карту **плана** (предполагаемое лечение после вмешательства). Присутствует только тогда, когда карта плана была инициализирована И её содержимое отличается от карты статуса. При импорте отсутствие `plan` очищает/деинициализирует карту плана; присутствие `plan` восстанавливает карту плана вместе со статусом. Также читается/записывается независимо через `getPlanChart()`/`setPlanChart()`.

**Поле верхнего уровня `case` (версия 2.17+, расширено в 2.18, 2.19, 2.20 и 2.22):**
- `case` — необязательный объект, содержащий метаданные уровня случая (не по зубам), общие для карт статуса и плана. Опускается, если пуст. Поля (каждое опускается при значении по умолчанию): `age`; `smokingStatus` (+ `cigarettesPerDay`); `diabetesStatus` (+ `hba1c`); `toothLossPerio`; `maxRblPercent`; четыре клинических переопределения по осям классификации 2017 года `diagnosisOverride` / `stageOverride` / `gradeOverride` / `extentOverride`; `patientName` / `examDate`; `patientDob`; и (версия 2.22) `caseConditions` — диагнозы случая/региональные диагнозы (прикус и ВНЧС K07, кисты полости рта K09, заболевания слюнных желёз K11, стоматит и заболевания слизистой оболочки полости рта K12/K13, аномалии развития на уровне дуги K00), каждый сопоставлен со стороной поражения (unspecified/left/right/bilateral). Читаются/записываются через `getCaseMeta()`/`getCaseConditions()` и сеттеры `set*`/`setCaseCondition()` выше. Имя пациента, дата рождения и дата осмотра — это только метаданные идентификации карты — они **не** входят в экспорт FHIR.

### 🖨️ Экспорт
`exportFhir()` «чист» для HL7-валидатора: каждая запись Bundle несёт детерминированный `id` и абсолютный `fullUrl` (без плейсхолдеров `urn:uuid`), а Bundle встраивает собственный CodeSystem движка, чтобы его локальные коды разрешались при валидации (также опубликован в `projects/angular-advanced-odontogram/src/lib/fhir/`; передайте `includeCodeSystem: false`, чтобы не включать его в Bundle).

Пародонтальные данные теперь тоже проходят round-trip через импорт FHIR, а не только через JSON payload: `importFhirBundle()` считывает пародонтальные панели LOINC `74029-0` обратно в пародонтальную запись каждого зуба — глубину зондирования, десневой край (восстановленный из CAL, поэтому значения псевдокармана сохраняются), BOP, фуркацию, зубной налёт по O'Leary, индексы PI/GI и импланта mPI/mBI, а также ширину кератинизированной десны — плюс наблюдения-доказательства статуса курения и HbA1c на уровне случая. Суппурация — единственное исключение: она остаётся только в JSON, поскольку не входит в экспорт FHIR.

Помимо собственного экспорта одонтограммы в Статус JSON / FHIR / PNG / JPG / SVG, **пародонтальная карта** имеет собственный путь экспорта:
- **Пародонтальный SVG/PNG/JPG:** `exportPerioSvg()` / `exportPerioImage("png"|"jpg")` отрисовывают полную пародонтальную карту в виде одного самостоятельного векторного SVG, независимо от смонтированного DOM `PerioChartComponent`. Отключён всегда, когда `hasAnyPerioData()` равно false.
- **PDF-отчёт:** пункт меню экспорта «PDF-отчёт…» открывает `ExportOptionsModalComponent` — диалог настроек (поля имени пациента, даты рождения и даты осмотра, напрямую связанные с метаданными случая, при этом дата осмотра по умолчанию — сегодняшняя; флажки разделов: данные пациента, зубная карта, описание одонтограммы, индивидуальные заметки — недоступен, если ни у одного зуба нет заметки — пародонтальный статус, описание пародонта) перед вызовом `exportPdf(opts)` через инъекционный токен `EXPORT_PDF_FN`. Пустые поля идентификации заменяются значениями-плейсхолдерами (`"John Doe"` / `"1980-01-01"`, настраиваемыми через `PdfSettings.defaultName`/`defaultDob`), чтобы экспорт всегда завершался успешно. PDF собирается нативно средствами jsPDF — векторный текст через `.text()`, растровые изображения зубной карты/пародонтальной карты через `.addImage()` — без зависимости от `svg2pdf.js`. Раздел индивидуальных заметок автоматически пропускается, если ни у одного зуба нет заметки, а оба пародонтальных раздела — если `hasAnyPerioData()` равно false, независимо от флажков диалога.
- **Конфигурация отчёта (`PdfSettings`, Настройки → вкладка «Экспорт», получение/установка через `getPdfSettings()`/`setPdfSettings(patch)`):** имя/дата рождения пациента по умолчанию, показывать ли возраст, формат даты (ISO/DMY/MDY), цветовая тема (blue/teal/amber/slate), видимость кости/пульпы на одонтограмме, интервал между зубами/рамка/размер номера зуба на изображении карты, включать ли текстовое описание и таблицу находок, соответствующие опции интервала/размещения меток/размера шрифта пародонтальной карты и включать ли таблицу пародонтальных показателей и глоссарий сокращений, медицинский дисклеймер (текст по умолчанию или пользовательский), отметку генератора/версии, а также группировку сводки прикуса (вся полость рта / челюсть / квадрант / секстант — также управляет таблицей экранной панели информации о зубах).
- **Ограничение mPI/mBI по имплантатам:** периимплантные индексы Mombelli (mPI/mBI) отображаются как строки только в той дуге, которая содержит хотя бы один зуб-имплантат — как на живой пародонтальной карте, так и в экспорте SVG/PDF.
- Имя пациента, дата рождения и дата осмотра — это только метаданные идентификации карты (payload `2.20`, аддитивно) — они **не** входят в экспорт FHIR.

- `projects/demo/` — демонстрационное Angular-приложение (`ng serve` / `npm run build:demo`)
- `scripts/generate-svg-assets.mjs` — генератор `npm run gen:assets`

### ⚙️ Технологический стек
- Angular 21 (standalone-компоненты, сигналы) + Angular CLI (`@angular/build`) + TypeScript
- `ng-packagr` для сборки библиотеки (`ng build angular-advanced-odontogram`)
- Tailwind CSS для стилизации интерфейса, компилируется один раз в статическую таблицу стилей (`npm run build:styles` → `projects/angular-advanced-odontogram/styles.css`) — потребители регистрируют эту таблицу стилей, сами Tailwind не запускают
- Слоирование SVG через манипуляции с DOM в ядре без привязки к фреймворку (состояние, не реактивное для Angular, — ради производительности; тот же движок, что использует оригинал на React)
- Лёгкая пользовательская система i18n без привязки к фреймворку (`core/i18n/`), обёрнутая `I18nService` для реактивной привязки в Angular-шаблонах
- Два раннера тестов: обычный Vitest для корпуса ядра (`vitest run`), интеграция Vitest `@angular/build:unit-test` Angular для спецификаций компонентов (`ng test`); `@testing-library/jest-dom` для DOM-матчеров
- TypeDoc для документации API (`npm run docs`, вывод в `docs/api/`)
- jsPDF для PDF-отчёта; DOMPurify для санитизации вывода плагинов

### 📝 Примечания
- SVG-шаблоны и иконки компилируются в сгенерированные TypeScript-модули на этапе сборки (`npm run gen:assets`) — загрузка ресурсов во время выполнения не требуется, и нечего обслуживать из публичной папки.
- Движок одонтограммы использует собственное внутреннее состояние без привязки к фреймворку (не сигналы Angular) для SVG-сетки — ради производительности и для сохранения полной идентичности оригиналу на React; Angular-компоненты читают его реактивно через `engineState()`/`I18nService`/`onStateChange()`, а не владеют им сами.
- Молочные зубы имеют сокращённый набор доступных материалов (без амальгамных пломб, без эндодонтии со штифтами).
- Зубы-имплантаты имеют другой набор вариантов коронок/абатментов по сравнению с натуральными зубами.

### 🔒 Примечания по безопасности

- **Плагины выполняются как доверенный код.** Возвращаемое значение `renderSvg()` плагина внедряется в SVG живой карты. Этот вывод санитизируется библиотекой [DOMPurify](https://github.com/cure53/DOMPurify) (SVG-профиль плюс `svgFilters`) перед вставкой — `<script>`, `<iframe>`, `<object>`, `<embed>` и `<foreignObject>` запрещены полностью, а полностью вредоносный вывод отбрасывается, а не частично отображается. Это снижает радиус поражения при компрометации или ошибке в плагине, но плагины по-прежнему следует загружать только из источников, которым вы доверяете — санитизация является дополнительной защитой, а не заменой проверки.
- **Content-Security-Policy.** Этот пакет не внедряет собственную CSP при использовании в качестве библиотеки. Приложения-хосты, отрисовывающие `OdontogramShellComponent`, должны задавать собственную CSP, соответствующую их развёртыванию; разумной базовой линией служит политика демо-приложения оригинального проекта на React:

  ```
  default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self'
  ```
